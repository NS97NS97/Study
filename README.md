# Рекомендательная система «Монеты для клиента»

Прототип (MVP) рекомендательной системы из ТЗ проекта: подбор монет для клиента по
трём критериям одновременно — **новизна**, **соответствие интересам**,
**соответствие бюджету** — с ранжированным перечнем кандидатов и текстовым
обоснованием релевантности.

## Быстрый старт

Требования: Python 3.10+. Один раз:

```bash
pip install -r requirements.txt
```

**Дальше — только двойной клик по файлу `Запустить.bat`.** Он сам скачивает
свежую выгрузку Google Таблицы, пересчитывает рекомендации, готовит файл для
вставки во вкладку «Рекомендации», собирает Excel-дашборд и открывает результаты
с инструкцией «что делать дальше» (см. [«Как пользоваться»](#как-пользоваться-один-запуск)).

Команды для разработки:

```bash
python -m recommender                        # полный прогон по локальному файлу
python -m recommender --input data/coins.xlsx --out reports --top-k 5
python -m recommender --google --dashboard   # + свежая выгрузка и Excel-дашборд
python -m recommender --google --dashboard --open   # то же + открыть файлы = Запустить.bat
```

Ноутбук для заказчика (пошагово, с графиками):

```bash
python tools/build_notebook.py
python -m nbconvert --to notebook --execute --inplace notebooks/01_рекомендательная_система.ipynb
```

## Как пользоваться: один запуск

Всё управление — **двойной клик по `Запустить.bat`**. Под капотом выполняется
`python -m recommender --google --dashboard --open`: свежая выгрузка Google
Таблицы → расчёт → файл для вставки рекомендаций → Excel-дашборд → открытие
результатов с инструкцией «что делать дальше». Если интернета нет, берётся
последняя локальная копия `data/coins.xlsx` (об этом написано в шапке дашборда).

### Шаг 1. Рекомендации во вкладку «Рекомендации» (gid=115404378)

Запись в Google Таблицу из кода не выполняется — на неё нужен разрешённый
канал, поэтому система готовит `reports/Рекомендации_для_вставки.xlsx`
и человек вставляет строки в два клика:

| Требование | Как реализовано |
|---|---|
| одна строка = одно предложение «монета → клиенту» | ровно столько строк, сколько пар: сейчас 5 клиентов × топ-5 = 25 |
| атрибуты монеты — из вкладки «Сделки» | `ID монеты, ГП2, Княжество, Князь, номинал, описание, R, вход` копируются как есть; где в «Сделках» пусто — остаётся пусто (оценочные значения не подставляются) |
| «за сколько» и «предложено» не заполняются | эти колонки **не входят в файл вообще**, поэтому при вставке не затираются ваши ручные отметки |
| дозапись в конец | пары «монета + клиент», уже существующие во вкладке, исключаются, прежние строки не трогаются |

Вставка: вкладка **«Копировать»** → ячейка A1 → `Ctrl+A` → `Ctrl+C` → в
Google Таблице вкладка **«Рекомендации»** → первая пустая строка → `Ctrl+V`.
Номер этой строки система пишет в инструкцию и в консоль при каждом запуске.

### Шаг 2. Дашборд `reports/Дашборд.xlsx`

**книга Excel, которая сама берёт данные из Google Таблицы по ссылке**
(`recommender/config.py` → `GOOGLE_SHEET_URL`).

| Лист | Содержание |
|---|---|
| **Дашборд** | 8 карточек KPI, топ-5 рекомендаций для каждого клиента с обоснованием, 5 диаграмм (статусы каталога, наличие по княжествам, бюджет vs цена, HitRate@K против бейслайнов, результаты аудита) и предупреждение при критичных ошибках данных |
| Рекомендации | полный список с колонками «Итог» и «Обоснование» |
| Профили клиентов | интересы и бюджетный коридор по каждому клиенту |
| Каталог монет | все 57 монет, у доступных — оценка цены по аналогам |
| Качество данных | 30 проверок, уровни OK / WARN / FAIL |
| Метрики · Метрики (настройка) | качество offline-теста и анализ чувствительности |
| Как обновить | инструкция внутри книги — отдельно читать документы не нужно |
| `_графики` (скрытый) | исходные данные диаграмм, обновляется автоматически |

## Ключевые результаты

**Данные:** 57 монет (47 продано, 10 доступно), 5 клиентов, 47 сделок за
01.12.2025–29.09.2026.

**Аудит:** 30 проверок → 26 OK, 3 WARN, 1 FAIL. Единственный FAIL —
`ДАТА ПОКУПКИ` не заполнена ни по одной сделке, поэтому KPI Y («закупка →
продажа») на истории не считается (см. `docs/Требования_к_данным.md`).

**Качество offline (temporal leave-one-out, 42 оценённые сделки):**

| Метод | Покрытие | HR@1 | HR@3 | HR@5 | MRR |
|---|---:|---:|---:|---:|---:|
| **Модель (3 критерия, строгие фильтры)** | **73.8%** | **0.071** | **0.167** | **0.262** | **0.158** |
| Модель (скоринг без фильтров) | 100% | 0.071 | 0.190 | 0.333 | 0.192 |
| Бейслайн: популярность (те же фильтры) | 73.8% | 0.048 | 0.143 | 0.262 | 0.147 |
| Бейслайн: наугад (те же фильтры) | 73.8% | 0.041 | 0.123 | 0.200 | 0.135 |
| Бейслайн: наугад (без фильтров) | 100% | 0.037 | 0.112 | 0.187 | 0.141 |

При одинаковом покрытии модель уверенно бьёт оба бейслайна по точным метрикам
(HR@1, HR@3, MRR) — ранжирование отбирает релевантное наверх.

**Пример выдачи (Шувалов, топ-3 из 5):**

| # | ГП2 | Княжество / князь / номинал | Цена | Итог |
|---|---|---|---:|---:|
| 1 | 1300 | Москва / ВД / денга | 40 000 ₽ | 0.954 |
| 2 | 1111 | Москва / ДД / денга | 40 000 ₽ | 0.847 |
| 3 | 7100A | Тверь / БА / денга | 20 000 ₽ | 0.840 |

Полное обоснование каждой рекомендации — в `reports/recommendations.xlsx`
(колонка «Обоснование»).

## Как это работает

```
данные → аудит → профиль клиента → три фильтра → скоринг → топ-K + обоснование
```

1. **Новизна** *(жёсткий фильтр)* — ГП2 и мотив монеты не встречаются среди
   покупок клиента. Не ослабляется никогда.
2. **Профиль** *(ранжирование)* — доля покупок клиента по княжеству, князю,
   номиналу, мотиву описания и редкости, отнормированная на максимум предпочтения.
3. **Бюджет** *(жёсткий фильтр)* — цена монеты внутри коридора клиента
   (расширение интерквартильного ограждения, минимум ±50% от медианы). Если
   строгих кандидатов мало — допуск расширяется до ±60%, строка помечается как
   `эскалация`.

Итог: `score = 0.20·Новизна + 0.50·Профиль + 0.30·Бюджет`.

Подробности, формулы и ограничения — в [`docs/Методика.md`](docs/Методика.md).
